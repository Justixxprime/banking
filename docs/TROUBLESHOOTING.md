# Troubleshooting

If `npm start` says a module is missing, run `npm install`. If you see an old `better-sqlite3` binding error, run `npm install` again after pulling the current project files. If port 3000 is already in use, stop the existing server with `Get-Process node | Stop-Process`, then run `npm start` once. Do not run a second server while the first one is active. If a newly added page shows `Not found`, it usually means the browser loaded updated frontend files but an older Node server is still running; stop Node, start it again, then press `Ctrl+F5` in the browser. If you see `DATABASE_URL is missing`, create `.env` from `.env.example`. If start-up says it cannot connect, check the full Neon connection string and use `?sslmode=verify-full`; a sleeping Neon database can take a few seconds to wake. To reset the dev database, run the migration with `--replace`, or reset the Neon `dev` branch from the Neon console.

If a page or notification still shows wording you already removed from the source, the text is stored in a database row rather than in the code. Editing `seedDatabase` only changes a fresh, empty database, so add a numbered migration in `src/database.js` that updates the existing rows; it runs on the next `npm start`. Restart the server so the migration is applied, then reload the page.

If Print or Save-as-PDF produces a blank sheet, the print stylesheet is hiding the content that should appear on paper. Only the children of `body` behind an open modal may be hidden, and they must be hidden with `body:has(> .modal-v2)` so a view rendered inside `#app` (such as a receipt page) still prints. Check the print block in `public/app-v2.js`, and confirm the account dropdown still has its styling, since a malformed selector in that same block is dropped silently by the browser.
